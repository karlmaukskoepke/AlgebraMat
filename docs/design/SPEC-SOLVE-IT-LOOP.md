**What this is.** One document for everything every Solve it card shares. **Each card is only problem-type configuration** (its moves, levels, forms, slips, scaffold pictures). **Precedence:** if a card spec and this document disagree on a shared rule, this document wins. ## 1. The loop in one page

Every problem is a series of **equation states**: the original, then the equation after each correct move.

```
STATE (x not alone)
 ├─ hover a move ─► grey ghost-row preview with dashed blanks ─► click ─► type the amount ─► green button
 │       ├─ helpful ─► new row written (under a rule line) ─► NEW STATE
 │       └─ unhelpful ─► spotlight pop-up, Undo pulses ─► Undo ─► hint pop-up ─► same STATE
 ├─ grab a term (drag / tap the minus) ─► grey preview of where it lands ─► drop ─► same as a move
 └─ type x = value (always live) ─► green button "Check" ─► the check (§4)
        ├─ balanced ─► green "Next"
        └─ not balanced ─► pop-up, Undo (pulses) ─► hint pop-up
x ALONE ─► `x =` is the last step, and the only place that blinks
```

### 1A. No choice, no banner
- There is **no "Guess x / Use a move" choice.** The `x =` field is **always live**, at every state, and never blinks except when x is alone.
- **The top banner no longer exists.** Every message is a **pop-up** (§2A). One-time first-problem pop-up: "Find the value of x."

### 1B. Guesses, the final value and the forced move
- A wrong value at any state is checked (§4) against the **current** equation if x is not alone, or the **original** equation if x is alone. Then Undo, then the hint pop-up (§6).
- **Correct value, any state:** the check ends Balanced; the green button reads **Next**.
- **Forced-move rule.** If the correct value came at the **first state with zero moves made**, the **next problem** is a forced move: everything greys out except the new problem and the moves panel, and a pop-up says "Your mental math is very strong. / Let's try solving this next problem using a move first." The needed move is ringed and pulses. The `x =` field is greyed until one move is made. The pop-up is dismissed by **Next** or by choosing a move. Hovering a move un-greys it and lights its preview. The following problem is free.
- If that guess was the last problem of a level, a sixth, move-only problem is added.
- **x on both sides (rev 2.6).** On a card whose equations have x on both sides (Variables on both sides), the student must get x on one side before checking: `x =` is greyed, with the note "Get x on one side first.", until x is on only one side; then it is live as everywhere. There is no guess at the first state, so no forced-move rule on such a card.

### 1C. Moves
- **Hover** (focus, or first tap on touch) on a move shows a grey ghost row with dashed blue blanks; **click** makes it solid; the student types **one** blank (mirrored on both sides, sign included, 0 refused), then the green button (**Go** word: "Do it"). The result is written under a **rule line**.
- **Cancelling** shows on x's side; the other side is left unsimplified until the student types the value.
- **Helpful move:** new row, new state. **Unhelpful move:** spotlight pop-up (§2A); Undo is the only exit. Illegal moves do not exist.
- **Undo** reverses the current move only. **Start over** wipes the stack; it is greyed on the untouched original; the stuck count survives it.
- **Add** is the only additive move: "Add ___ to both sides", a positive or a negative (the addition property of equality). **There is no subtraction move** (rev 2.4); no card offers or names "subtract ___ from both sides" as a move. Arithmetic inside help ("Subtract 13 − 9") is arithmetic, not a move, and stays. **Adding an x-term is written in a column (rev 2.8, Build T):** Add's x-term option (where a card has it: Variables on both sides) shows a dashed box under the first x-term of each side (its first term where it has none), `+ ▢x`, the x printed after it. Either box takes the keys and the other shows the same amount (one amount, both sides); Tab goes between them, a click retypes, Go or Enter applies, zero is refused. The work row writes the amount under the x-term it was added to (the row one line taller), crosses out the pair that cancels and nothing else, and the new row puts the added x-term right after that x-term, so like terms sit together (`5x + −2x + 5 = 14`). An x-term that cancels no x-term gets the spotlight ("Add so that one x-term cancels. To cancel 2x, add −2x.") and, after Undo, the x-term option open with that amount. A number stays in line, as before. An x-term dragged across the = is the same Add: its preview, its column and its place are the same (a number dragged across still lands where it is dropped).
- **Only one move is selected at a time.** Choosing another move clears the first one's selected (yellow) state as if it had not been clicked; applying or cancelling a move clears it too. **A hover preview lasts only as long as the hover:** leaving a move ends its preview at once; moving to another move swaps to that move's preview; leaving every move leaves a clean equation (the same for keyboard focus, and for touch: a tap elsewhere clears it). A selected move keeps its own solid preview until it is applied or cancelled.
- **The Multiply menu (rev 2.9; rev 2.4 had two options).** The one Multiply button opens three options beside it, each with a larger drawn symbol floating to its left (the panel's style, §2); each previews on hover (grey ghost row, dashed blanks) and becomes solid on click:
  1. **Whole number** (`n ( ) = n ( )`, symbol ×): one whole-number blank, negatives allowed. Typing **−1** is **Flip everything** (the same move, preview, row, class-sheet record and tags as the Flip button). A `/` typed here switches to the Fraction option, keeping the typed digit as its top.
  2. **One over a blank** (`1/▢ ( ) = 1/▢ ( )`, symbol ÷; Build L's option, back): the `1/` printed, the student types one digit, a minus allowed (−3 is written −1/3); a `/` is ignored. Drawn in multiplication form, `⅕(5x) = ⅕(−15)`, with a small line under the row: "Dividing by 5 is multiplying by 1/5." Stored, checked and recorded as the Fraction option with a top of 1. Live wherever the Divide button is live (the same single-term rule and the same messages).
  3. **Fraction** (`▢/▢ ( ) = ▢/▢ ( )`, symbol a small fraction): the fraction blank (Build D-2 and H: the cursor starts in the top and jumps to the bottom after one digit; a click or tap on a box clears it and puts the cursor there; the top may be negative where the card allows it). Rows are drawn in multiplication form, `⅕(5x) = ⅕(−15)`.
  **Division is reachable two ways on purpose** (the Divide button and the middle option): a student who opens Multiply may notice a division option and question it. Hints still light the Divide button.
- **The Divide button (rev 2.4)** is a second way in to the same move, with a visible division form: its icon is `( )/n = ( )/n`. Hover (or selecting it) draws a big fraction bar under both sides of the equation with a blank beneath each bar; the two blanks mirror, as Add's do. The student types **one digit**, a minus allowed ("Enter a one-digit number to divide by." beside the blank for a second digit), and Go applies. **Display only:** the stored move is multiplication by 1/n (`−1/3` for −3), so the check, shapes, class-sheet record, lights and save bits are those of taking 1/n. A row made with the Divide button is drawn in division form, `(5x)/5 = (−15)/5`, then `x = (−15)/5`, with a small line under it: "Same as multiplying by 1/5." (rev 2.9: on a line of its own, reserved, never touching the next row). Dividing by −3 writes −3 under each bar. Dividing by −1 is Flip everything (stored, checked and recorded as the Flip button's move) but is drawn in division form, `(−x)/(−1) = (12)/(−1)`, then `x = (12)/(−1)` (rev 2.5). Dividing by a negative has its own pop-up once a level: "Dividing by −1 does the same thing as multiplying by −1: every sign flips." / "Dividing by −3 flips every sign, just like multiplying by a negative does, and then divides by 3." (Divide it, where −1 is explained, keeps its message.) The Divide button follows the single-term rule (live only when each side is one term; a parenthesis counts as one), with each card's greyed messages, and a fraction that does not split gets Divide it's fraction cycle (`SPEC-DIVIDE-IT.md`).
- **Flip everything** is its own panel button, not a Multiply option. On a card where Flip is greyed, a typed −1 gets that card's greyed message.
- A card turns moves and options on or off; the panel and the menu never change shape. A greyed option says "That move unlocks on a later card." (or "…later level." where a level gate applies), or the card's own reason (Two-step: "That move works once each side is one term."). Which are on: Divide it, Divide and Fraction (unit fractions), the whole number live but explained (rev 2.5: "5 × (5x) makes 25x: still not one x. Try dividing both sides.", and its `/` opens the fraction); Flip everything, Flip, and from saved Level 4 Divide and Fraction (−1/a in one move accepted); Two-step and Distribute, combine, solve, Divide and Fraction under the single-term rule; Add to both sides, no multiply-type move. Whole number is greyed on every other card today.

### 1D. Grabbing terms (manipulable equations)
- **Reorder** a term by dragging; **cross the midline** to flip its sign and write both-sides work automatically (constants today; x when x is on both sides); **combine** by dropping a constant on another (both light, rest greys out, the word "Combine" over them, a box below for the typed sum; auto-combine at later levels is a flag, off); **tap a minus** to make it `+ −2` (needed before distributing); **distribute** by dragging the whole factor onto the parentheses.
- **The wrong cancel (rev 2.8): a deliberate exception to "a legal move is never red".** An Add (a number or an x-term, by the button or by dragging across the =) that leaves 0 on one side and an x-term and a number together on the other (`5x = 3x + 10` + −5x makes `0 = 3x + 10 − 5x`) gets the spotlight (the 0 marked "nothing left", the other side lit): "We want the x-terms on one side and the numbers on the other. That Add took everything off one side. Undo, then cancel just one x-term." Only Undo. **Any sign (rev 2.9, Karl's rule):** the error is not separating the x-terms and the numbers onto opposite sides, so `2x = 3x + 6` + −2x (`0 = x + 6`) is flagged too. The hint after Undo never sends the student back to the same move: it opens Add's x-term option with the x-term on the side that holds the number, so the number ends alone on its side (`2x = 3x + 6`: "Add −3x to both sides: the 3x cancels, and the number is left alone on its side.", giving `2x + −3x = 6`; a negative number in front of x afterwards is fine, Flip handles it; where both sides hold a number, the smaller x-term), or, after a number, Add's number option with the opposite of the number beside x; recorded as `hint`, slip tag `zeroed-side`. The reminder at x on both sides (V1) follows the same rule: where one side is a lone x-term, it outlines the x-term on the other side. Two-step's and Add's own zero case (a lone number zeroed) keep their message.
- **Every drop works or says why (rev 2.7).** A term dropped where it can go moves (across the =, onto a like term, between terms; from either side of the =, whether or not the move before it has been folded). A drop that cannot work puts the term back with its reason: an x that would leave its only side (rev 2.8: its words end with a move that applies to that side's shape: move the number where there is one, divide at `ax = b`, type the value at x alone, combine or distribute first), a term onto an unlike term or a parenthesis ("Only like terms combine…"), a parenthesis's factor let go anywhere but its parenthesis. Dropped where it was, or away from the equation, a term simply goes back.
- **Distributing (rev 2.5, Build P).** When the factor is dropped on the parenthesis it is shown in colour with an arc to each piece inside, a small × on each arc, and "3 groups of" by the parenthesis; the blanks carry **no operation label** (the x blank keeps its printed x). After a wrong product the labels (`3 · x`, `3 · 2`) appear above the blanks as the scaffold (recorded as `hint`) for the rest of that problem; the next problem starts without them. **Undo after a wrong typed amount goes back to its blank (rev 2.8):** after a wrong product the distribute stays in progress (the factor in colour, the arcs, "3 groups of", the labels), the blanks empty and the cursor in the first, with "Try again: type what 3 · x and 3 · 2 make…"; after a wrong sum or a wrong worked-out product its two terms stay lit and its blank is empty and focused ("Try again: what is 19 − 4?"). No gesture is repeated. Add's amount already returned to its blank (Build A). A second Undo closes the blank.
- **Calculate a product (rev 2.5, Build P).** After dividing first (or taking a fraction) a side can read `⅓(15)` (division form `(15)/3`). While x is not alone, the small × between the factor and the number (in division form, the fraction bar) is a button: it opens a blank for the signed product (like a sum's); Enter or Go writes the side as that one number (`x + 2 = 5`). A wrong product waits for Undo with the factor and number lit, then the hint ("⅓ × 15 is the same as 15 ÷ 3. Click the × and type it."). Never at x alone (`x = ⅓(15)`): the student types x.
- **While dragging:** a grey preview of the landing expression in place; the token is **green** (positive) and turns **red** over the midline with the new sign; the midline is thick and obvious and shown **only while dragging**; the destination side is tinted.
- **Dragging x** off an already-alone-on-the-left x gets the info pop-up "x is already on the left side of the equation. Let's keep x there. Try moving a number." Allowed when x is on both sides.
- Every drag has a tap or keyboard alternative; pointer events with a 6 px threshold; `touch-action: none` on grabbables.

## 2. The screen (bare, stable)

1. **Header and level dots:** shown for about 3 seconds at the start of each problem, then a thin strip; hovering the top brings them back.
2. **The solving space (left):** the equation, then rows of work (**older lines in lighter ink so the newest stands out**), then `x =` with **the one green button** to its right.
3. **The check space (right of the solving space):** empty until a value is checked (§4). No labels, a faint dotted line or space between.
4. **The moves panel:** headed **"Moves"** (small and quiet), a **narrow column of icons** (44 px, spaced vertically), each with a **larger drawn symbol floating to its left** (about 24-28 px, ink, with an accessible name): + Add, × Multiply, ÷ Divide; Flip everything (rev 2.9): two rounded arrows making a circle, a minus at the left and a plus at the right, one arrow curving up and right from the minus to the plus and the other down and left back to the minus ("Cycle between minus and plus"); Trade places (rev 2.9): an equals sign with the same two circling arrows round it ("Equals sign with two circling arrows"). Hover and focus show the move's **formal property of equality** (§5) and the preview; the pointer **approaching** (about 40 px) starts the preview early. **The lights** stay as a small collapsed column on the right: hover expands a goal. Smaller numbers and One box sit beside Divide (rev 2.5), No fractions beside Multiply. They are a curiosity, not a requirement.
5. **Help is tucked** into a corner: **I'm stuck** flashes gently after **10 s of no action**; **Teach me** appears only after a **second error** on the problem, and flashes when it appears. Start over lives in the same corner.
6. **Keyboard first.** No number pad on devices with a keyboard; on touch devices a compact keypad pops up only while a field is focused.

### 2A. Pop-ups (one component, one rule)
- **Placement:** below wherever the action is; if there is no room, the nearest free space that covers **no equation or work**. It may cover greyed-out things such as the `x =` field.
- **Spotlight (error) pop-up:** dims the page, lights the error, message beside it, **Undo pulses with a hopping arrow** (steady arrow under reduced motion) and is the only exit. **I'm stuck / Teach me are ignored while it is up.** After Undo, a **hint pop-up** (the reminder rung) appears.
- **Info pop-up:** no dimming; closes on the next action.
- **Nudges** with nothing to undo ("type a number") are small pop-ups beside the field.
- The word "still here" after a move that fails to cancel sits below the number it points to.
- **Nudges for mechanical steps (rev 2.5).** After about **2.5 s with nothing happening** (any key, click or drag resets it), when the
  next step is **mechanical and there is only one thing to do**, the target glows and pulses for 1-2 seconds; if still nothing, a small
  pop-up says what to do (placed by the rule above, never over the equation or work) with a faint ghost of the action. Under reduced
  motion, a steady highlight instead of a pulse. It repeats gently, never stacks, never shows while a spotlight, error, scaffold or
  another pop-up is up, and clears on any input. Today's nudges: **combine** (a side holds two numbers or two x-terms that go together,
  x is not alone, nothing else is pending: "Drag one onto the other to combine them.") and **calculate a product** (`⅓(15)` beside a side
  that is not x alone: "Click the × to work out ⅓ × 15."; division form: "Click the fraction bar to divide 15 by 3."). **Choosing a move
  is never nudged:** that is the thinking, and it waits for I'm stuck. A nudge is not help and records nothing. The 10-second I'm
  stuck flash is separate and unchanged.

### 2B. Screen rules
- **One forward button.** **One big green button in exactly the same place on every screen** (right of `x =`). Only its word changes (Check, Next, Do it, Combine, Got it). Greyed when there is nothing to do. Enter presses it. No separate check mark.
- **Only one thing is lit at a time.** **No cursor or `x =` blinks** except the final `x =` step.
- **Nothing advances on a timer** except the problem-start header fade and the help-flash timers above.
- **Layout is stable;** no reflow when a row is added. **Phones are secondary:** Chromebooks and laptops first; every drag has a tap alternative.
- **A redraw changes only what changed (rev 2.7).** An entrance or cross-off animation plays once, when its row or mark first appears. A redraw for any other reason (a pickup, a key, a click, Undo, a hover, a pop-up, a nudge) leaves every row already on screen exactly as it was: never replayed, never blanked, never taken off and put back. Picking up a term leaves a dashed gap where it was and changes nothing else.
- **Never grey out what the question is about.** Whatever the student is being asked about (the numbers in `−8 + 11`, the equation being solved, the two sides that failed to balance) stays at full strength and readable during any pop-up, spotlight or scaffold. Other things grey around it.
- **Answers:** one whole number typed into `x =` (or the blanks). The solved value is never displayed before the student types it.

## 3. The work stack in detail
*(unchanged from rev 1.2 except as noted)*

- **3A. Folding.** Only the current move shows full work; **Next** folds it to one row. **Undo reaches only the unfolded move.** Start over wipes the stack.
- **3B. Fit.** The generator reports the worst-case row count; Claude Code renders it at 1366×768 and 1366×650; if it fails, **fold more, never shrink text.** The check space (§4) uses the same reserved height. **One text size a problem (rev 2.7):** the size is chosen once, when the problem starts, from that problem's worst case (its honest path played ahead: the most rows, the widest row, the longest check, drawn out of sight at the window's size), the largest of 46/42/38/34/32 px at which nothing scrolls, no row runs past its space, and the check's pop-up has room away from `x =`; it never changes while the student works the problem (a row added or folded, a pop-up, the check, Undo, Start over). A new window size chooses again. **Row room (rev 2.9):** every row is tall enough for the tallest thing a row can hold (a division row with its bars and blanks, a group, a fraction, a cross-off), so nothing a lit area, outline, blank or pop-up anchor draws crosses into the next row, and the Divide row's "Same as multiplying by 1/5." line has a reserved line of its own. The extra room never lowers the chosen size: a problem that no longer fits folds sooner.
- **3F. A move whose signs cancel (rev 2.7).** A flip, or dividing by a negative, crosses each cancelling minus with a vertical stroke so it reads as a plus (a shape, never colour alone; rev 2.8: centred on the minus's bar, as far above it as below, never a T), one minus at a time, about 1.3 s each, then the row they make comes in. Reduced motion: both pluses drawn, still. **It can be skipped (rev 2.9):** any key, click or Next finishes it at once and goes on. The cross-off of the numbers (the two 3s) is unchanged.
- **3C. Highlighting each step.** The operation about to happen is coloured and **bold** (colour plus bold, never colour alone); its result appears in the same colour next line; one pair at a time; accent is unique (not green, red, blue or the added-amount colour). Never underline a row.
- **3D. The operation is blue** wherever it appears (prompts, pop-ups, rows, evidence).
- **3E. Work is shown at every step on every level**, evidence included.

## 4. Checking a value (side by side)

1. The student types a value in `x =` and presses the green **Check**. **Everything greys out except the original equation and the check space.** Pop-up: "Drag your value into each x." The typed value and every x blink. After 2.5 seconds with nothing done, a faint copy of the value travels from `x =` to the first x, again and again until the student acts.
2. **Drag the value onto each x** (every card). **Picking the value up** slides a faint shadow copy of the equation being checked into the check space, at the place its first line will take (the same faint look as the travelling value). **Dropping it on an x** makes the copy solid; **dropping it anywhere else** slides the shadow back and changes nothing. **Multiple x's need a drop each (rev 2.5), on every card:** while the value is dragged every empty x glows as a drop target; a drop fills that x only, with a small green check above it, and the other empty x's show a faint ghost of the value waiting; the copy completes and the steps begin once every x has the value. Nothing fills itself.
3. **The check, top to bottom (Build I):**
   - **Line 1: the equation being checked, exactly as written**, every x in the same blue as the x in the original.
   - **Line 2, directly below it: the same equation with the value in each x's place**, the value in blue (in parentheses when negative, as the rendering rules below say). **Each value sits directly under the x it replaced**, so the blue pairs read "this x became this number." A value wider than x moves the rest of line 2, never the pairing; if the first value reaches left of where line 1 starts, line 1 moves right as a whole. Line 1 is never stretched or squeezed, **except with several x's (rev 2.6): the two lines share one column grid**, so where a value is wider than its x (`2 × 7` under `2x`) line 1 opens a space before that x instead, and each blue value sits directly under its x. *(Known limit, two x's only: when a number in front of the second x adds a "2 ×" to line 2, the second value can sit to the right of its x; no card has two x's yet.)*
   - **Then one operation per press of the green Next**, as before, ending **✓ Balanced** (green) or **✗ Not balanced** (red). A wrong value lights the last row and Not balanced.
   - **On the seesaw** (opened by I'm stuck or Teach me), the balance mirrors the check: the original equation with an empty x box while the value waits (line 1), the x box swapped for the box of counters when it lands (line 2), then each line's combining.
   - The check space has one more row than before: 4 rows at worst (line 1, line 2, one worked line, the mark) on Add to both sides and Divide it; rendered at 1366×768 and 1366×650.
4. **No text ever covers the equation.** The rendering rules carry over: negative values in parentheses; **a product is written with parentheses, never with a times sign (rev 2.8)**, since × next to the x's reads as another x: `7(3)`, `−3(−4)`, `2(7)`, `3(3 + 2)`, at most a dot between two numbers; test cases `3x = −12`, −4 → `3(−4) = −12` · `−3x = 12`, −4 → `−3(−4) = 12` · `12 = −x`, −12 → `12 = −(−12)` · `7 = x + 3`, 4 → `7 = 4 + 3`.
5. **Wrong value pop-up:** "When x = 19, the equation is not balanced." (never "put 19 back into x"). Undo resets to before the guess.
6. **No collapsing (rev 2.5).** Every check on every card, at every level, shows the full order of operations, one step per press of Next or Enter, ending Balanced or Not balanced. A group is worked out visibly (`3(3 + 2) = 15`, `3(5) = 15`, `15 = 15`); in a longer equation each operation has its own line.

## 5. The moves panel and lights

- **Full move list on every card**, unused moves greyed so the panel never changes shape, in this order (rev 2.4): **Add** ("Addition property of equality: add the same number to both sides"), **Multiply** ("Multiplication property of equality"; its menu: whole number, one over a blank, fraction; §1C), **Divide** ("Division property of equality"; its own button, display only, §1C), **Flip everything** ("Multiplication property of equality: multiply both sides by −1"), **Trade places** ("Symmetric property of equality: if a = b, then b = a"). Cross the border, Distribute and Combine like terms are done on the equation itself (§1D). There is no subtraction move. Greyed moves say "That move unlocks on a later card." Moves are presented as **properties of equality** (the same rule on both sides), and the hover name is the property.
- **Lights** are an unranked checklist by default, shown as small dots on the right; hover expands the goal. Add judges only **Fewer terms** and **Solved for x**. A legal move is never red. Lights drive messages and class-sheet tags whether or not they are displayed.
- **Solved for x** is green when x is alone (a card may refine it).

## 6. Help

**Principle:** every support is something the student **does**, and ends by sending them back to try. Nothing opens automatically except the post-error sequence (§2A) and the forced-move pop-up.

- **Nudges are not help** (rev 2.5, §2A): a mechanical step with one thing to do is nudged after about 2.5 s; choosing the move waits for I'm stuck. Nothing is recorded.
- **Help talks in the form on the screen (rev 2.8).** A row made with the Divide button (drawn with a fraction bar) gets division words ("x is 15 divided by 3. Work it out, then type x."); a row made with the Fraction option (drawn `⅓(15)`) gets fraction words ("x is ⅓ of 15. Work it out, then type x."). Every reminder, hint after Undo, I'm stuck rung, refused drag, product pop-up and failed-division pop-up follows this; a division that does not come out even is said as one ("Press Undo and try another number to divide by."), and the choices after Undo are numbers to divide by (÷ 2 … ÷ 6, the Divide button lit). Before anything is divided, the hint naming the move may give both ways ("divide both sides by 5 (that is, multiply by ⅕)"). The row's own line "Same as multiplying by ⅕." is part of the division row, not help. A standing test checks every shape on every card in both forms.
- **Hint pop-up after Undo (the reminder rung).** Lights the needed move with its hover preview and the suggested amount where it helps. **When the next move is dividing (rev 2.9)** (`5x = −15`, `3x = 15` after a combine, a group after Distribute, `−3x = 12` on Flip), the hint shows a multiplication dot between the number and the x in that row (`5 · x`, only while the hint shows) and the Divide button's preview (the fraction bars with the box beneath); nothing is boxed. The same is I'm stuck's first rung; the second is the card's model picture ("Model it": boxes equal to the amount, the amount dealt out) where the card has one.
- **I'm stuck** (one rung per click, +1 stuck count): Model it / Choose the move / Guided; rungs restart at each new state; every rung gives the student something to do.
- **Teach me** is the same scaffolds on a forced path. On Add: pop-up "To cancel the +8 we add its opposite, −8, to both sides", **Add lit with its preview and the blank pre-filled**; the green button "Do it"; at x alone the Party/Battle bubble; then the counters walk if still stuck. It never writes the final value.
- **Party / Battle** (Karl's words): party = same signs join; battle = opposite signs, the bigger team wins. **The bubble always floats directly above the two numbers or counters in question, with everything else greyed out.** Afterwards the student crosses off opposite pairs (tap each counter or a whole box; automatic crossing allowed); **crossed-off counters stay visible** (struck through or faded) while the student counts what is left. Numbers over 12 use the big-number walk (no counters).
- **Misconception pop-ups by typed value:** typed the opposite of the number next to x (`x + 8 = …`, typed −8): "−8 is an important number, but it's not the value of x. It's what we add to both sides to find x." Then the hint lights Add with −8. Added the sizes (`−8 + 11` → 19, tag `sizes-added`): after Undo, Party/Battle above the operation. Cards may add one named misconception each.
- **Scaffold rules carried over:** a scaffold never blanks the stack; the picture stays until Next; every rung that has a picture shows it, including x alone with an unevaluated side; numeric levels offer no help.
- **Stuck count (teacher-visible):** per level, I'm stuck clicks and Teach me uses; anonymous scrambled ids only (hard district rule). The class sheet shows lights/goals per student (teacher view); words `hint`, `model`, `move`, `guided`, `crossoff`, `forced` and save-code meaning (v14) do not change.

## 7. Levels, numeric levels and the diagnostic
*(unchanged)* Five problems per level, no repeated answers; a new single-move card opens with a numeric level (no x, balance readout on) that can be skipped only after the diagnostic; combined-move cards have none. Save codes hold one bit per level; **displayed Solve it level numbers are one lower than saved** (Level 1 now goes straight to problems; "See why it works" is a button). Old levels map forward.

## 8. Generator rules (every card, every level)
*(unchanged)* Every problem verified by substitution in code; answers whole, never 0 or ±1; no repeated answers or equations within a level; at most 36 counters per side and 6 boxes (counters cap at 12 in Count it's help; Add goes to 15, over 12 uses the big-number walk); no accidental balances; slip collisions reported; required sign mixes per card; worst-case row count reported; lights computed on every state.

## 9. What a card spec must define
1. Task and move(s), with a worked example. 2. Levels and number ranges. 3. The move's picture and scaffold pictures. 4. Lights it judges. 5. Slips and misconception pop-ups. 6. I'm stuck rungs and Teach me where they differ. 7. Worst-case row count (no card collapses its check, rev 2.5). 8. Banned answers. 9. Diagnostic and old-level mapping. 10. Open items. **A card that needs a new engine is a new shape in the scaffold registry, not a new loop.**

## Conformance checklist (every card, every level)
1. **No banner.** Every message is a pop-up placed under the action and never covering the equation or work.
2. **One green button,** same place, only the word changes; `x =` never blinks except at x alone.
3. **Hover preview** on every move; one blank; the amount shows in blue on both sides.
4. **Spotlight sequence** on every error: dim, light, message, Undo pulses with arrow, hint pop-up after.
5. **Check is side by side;** value dragged into every x; line 1 the equation, line 2 the value under each x; steps on Next; no text over the equation.
6. **Work shown** at every step; operation in blue; no underline under check rows.
7. **Scaffolds show pictures,** never blank the stack, give something to do, and Party/Battle sits at the numbers with the rest greyed.
8. **Layout stable;** fit test run; worst-case rows reported.
9. **Generator verified;** banned answers; collisions reported.
10. **Shared code:** pop-up component, row builder, check renderer, operation colour, scaffold adapter are shared, not re-implemented per card.
11. **Class-sheet words and save codes unchanged.**
12. **Nothing the question is about is greyed.** The numbers, equation or sides being asked about stay fully readable during every pop-up, spotlight and scaffold (§2B).
