## 1. The loop in one page

Every problem is a series of **equation states**: the original, then the equation after each correct move.

```
STATE (x not alone)
 ├─ hover a move ─► grey ghost-row preview with dashed blanks ─► click ─► type the amount ─► green button
 │       ├─ helpful ─► new row written (under a rule line) ─► NEW STATE
 │       └─ unhelpful ─► spotlight pop-up, Undo pulses ─► Undo ─► hint pop-up ─► same STATE
 ├─ grab a term (drag / tap the minus) ─► grey preview of where it lands ─► drop ─► same as a move
 └─ type x = value (always live) ─► green button "Check" ─► the check (§4)
        ├─ balanced ─► green "Next"
        └─ not balanced ─► pop-up, Undo (pulses) ─► hint pop-up
x ALONE ─► `x =` is the last step, and the only place that blinks
```

### 1A. No choice, no banner
- There is **no "Guess x / Use a move" choice.** The `x =` field is **always live**, at every state, and never blinks except when x is alone.
- **The top banner no longer exists.** Every message is a **pop-up** (§2A). One-time first-problem pop-up: "Find the value of x."

### 1B. Guesses, the final value and the forced move
- A wrong value at any state is checked (§4) against the **current** equation if x is not alone, or the **original** equation if x is alone. Then Undo, then the hint pop-up (§6).
- **Correct value, any state:** the check ends Balanced; the green button reads **Next**.
- **Forced-move rule.** If the correct value came at the **first state with zero moves made**, the **next problem** is a forced move: everything greys out except the new problem and the moves panel, and a pop-up says "Your mental math is very strong. / Let's try solving this next problem using a move first." The needed move is ringed and pulses. The `x =` field is greyed until one move is made. The pop-up is dismissed by **Next** or by choosing a move. Hovering a move un-greys it and lights its preview. The following problem is free.
- If that guess was the last problem of a level, a sixth, move-only problem is added.
- **Levels without the rule (rev 2.16, Build AC).** A card may switch the forced-move rule off on chosen levels, as a setting on its levels (`noForcedMove`), never as a special case in the loop. Today: **Fractions of x Levels 1 and 3** (the model-first levels), where the model's steps count as the student's work: a correct value there, with the model or typed, never brings the pop-up or a forced move. Every other card and level keeps the rule.
- **x on both sides (rev 2.6).** On a card whose equations have x on both sides (Variables on both sides), the student must get x on one side before checking: `x =` is greyed, with the note "Get x on one side first.", until x is on only one side; then it is live as everywhere. There is no guess at the first state, so no forced-move rule on such a card.

### 1C. Moves
- **Hover** (focus, or first tap on touch) on a move shows a grey ghost row with dashed blue blanks; **click** makes it solid; the student types **one** blank (mirrored on both sides, sign included, 0 refused), then the green button (**Go** word: "Do it"). The result is written under a **rule line**.
- **Cancelling** shows on x's side; the other side is left unsimplified until the student types the value.
- **Helpful move:** new row, new state. **Unhelpful move:** spotlight pop-up (§2A); Undo is the only exit. Illegal moves do not exist.
- **Undo** reverses the current move only. **Start over** wipes the stack; it is greyed on the untouched original; the stuck count survives it.
- **Add** is the only additive move: "Add ___ to both sides", a positive or a negative (the addition property of equality). **There is no subtraction move** (rev 2.4); no card offers or names "subtract ___ from both sides" as a move. Arithmetic inside help ("Subtract 13 − 9") is arithmetic, not a move, and stays. **Adding an x-term is written in a column (rev 2.8, Build T):** Add's x-term option (where a card has it: Variables on both sides) shows a dashed box under the first x-term of each side (its first term where it has none), `+ ▢x`, the x printed after it. Either box takes the keys and the other shows the same amount (one amount, both sides); Tab goes between them, a click retypes, Go or Enter applies, zero is refused. The work row writes the amount under the x-term it was added to (the row one line taller), crosses out the pair that cancels and nothing else, and the new row puts the added x-term right after that x-term, so like terms sit together (`5x + −2x + 5 = 14`). An x-term that cancels no x-term gets the spotlight ("Add so that one x-term cancels. To cancel 2x, add −2x.") and, after Undo, the x-term option open with that amount. An x-term dragged across the = is the same Add: its preview, its column and its place are the same. **Adding a number is written in a column too (rev 2.14, Build Y; Karl, 2026-11-01), on every level of every card with Add:** the number option shows a dashed box under the first number (constant) of each side, `+ ▢`, digits lined up with the digits above, the sign beside them; a side with no number (only x-terms, or a group) gets its box at the end of its line, in line (`2x + 1 = 5x`, adding −1: `−1` under the `1` on the left, `5x + −1` on the right). With two or more numbers on a side it stacks under the first. The boxes behave as the x-term boxes do (either takes the keys, the other mirrors it, Tab between them, a click retypes, Go or Enter applies, 0 refused). The hover preview shows both placements before an amount is chosen. The work row writes the amount where its box was, crosses out the pair that cancels (Build W's stroke, 3G) and leaves the other side's amount for the student to combine; the new row is written as before (the amount at the end of a side it did not cancel). Only the chosen option's boxes are shown. Wrong and partial amounts get the same spotlights as before, the stacked amounts lit. A term dragged across the = is the same Add: its work row is the same column; it still lands where it is dropped.
- **Only one move is selected at a time.** Choosing another move clears the first one's selected (yellow) state as if it had not been clicked; applying or cancelling a move clears it too. **A hover preview lasts only as long as the hover:** leaving a move ends its preview at once; moving to another move swaps to that move's preview; leaving every move leaves a clean equation (the same for keyboard focus, and for touch: a tap elsewhere clears it). A selected move keeps its own solid preview until it is applied or cancelled.
- **The Multiply menu (rev 2.9; rev 2.4 had two options).** The one Multiply button opens three options beside it, each drawn as its own equation form and nothing else (rev 2.13: the symbols that floated left of each option are gone, Karl: no floating symbols anywhere); each previews on hover (grey ghost row, dashed blanks) and becomes solid on click:
  1. **Whole number** (`n ( ) = n ( )`; its preview and row are written `5(5x) = 5(−15)`, no times sign, rev 2.10): one whole-number blank, negatives allowed. Typing **−1** is **Flip everything** (the same move, preview, row, class-sheet record and tags as the Flip button). A `/` typed here switches to the Fraction option, keeping the typed digit as its top.
  2. **One over a blank** (`1/▢ ( ) = 1/▢ ( )`; Build L's option, back): the `1/` printed, the student types one digit, a minus allowed (−3 is written −1/3); a `/` is ignored. Drawn in multiplication form, `⅕(5x) = ⅕(−15)`, with a small line under the row: "Dividing by 5 is multiplying by 1/5." Stored, checked and recorded as the Fraction option with a top of 1. Live wherever the Divide button is live (the same single-term rule and the same messages).
  3. **Fraction** (`▢/▢ ( ) = ▢/▢ ( )`): the fraction blank (Build D-2 and H: the cursor starts in the top and jumps to the bottom after one digit; a click or tap on a box clears it and puts the cursor there; the top may be negative where the card allows it). Rows are drawn in multiplication form, `⅕(5x) = ⅕(−15)`.
  **Division is reachable two ways on purpose** (the Divide button and the middle option): a student who opens Multiply may notice a division option and question it. Hints still light the Divide button.
- **The Divide button (rev 2.4)** is a second way in to the same move, with a visible division form (rev 2.13: the button shows only ÷; the form is drawn on the equation). Hover (or selecting it) draws a big fraction bar under both sides of the equation with a blank beneath each bar; the two blanks mirror, as Add's do. The student types **one digit**, a minus allowed ("Enter a one-digit number to divide by." beside the blank for a second digit), and Go applies. **Display only:** the stored move is multiplication by 1/n (`−1/3` for −3), so the check, shapes, class-sheet record, lights and save bits are those of taking 1/n. A row made with the Divide button is drawn in division form, `(5x)/5 = (−15)/5`, then `x = (−15)/5`, with a small line under it: "Same as multiplying by 1/5." (rev 2.9: on a line of its own, reserved, never touching the next row). Dividing by −3 writes −3 under each bar. Dividing by −1 is Flip everything (stored, checked and recorded as the Flip button's move) but is drawn in division form, `(−x)/(−1) = (12)/(−1)`, then `x = (12)/(−1)` (rev 2.5). Dividing by a negative has its own pop-up once a level: "Dividing by −1 does the same thing as multiplying by −1: every sign flips." / "Dividing by −3 flips every sign, just like multiplying by a negative does, and then divides by 3. Many people flip first (· −1), then divide: two simpler steps." (rev 2.10: Karl teaches flipping first; dividing by a negative stays accepted) (Divide it, where −1 is explained, keeps its message.) The Divide button follows the single-term rule (live only when each side is one term; a parenthesis counts as one), with each card's greyed messages, and a fraction that does not split gets Divide it's fraction cycle (`SPEC-DIVIDE-IT.md`).
- **No times sign in written work (rev 2.10, Karl).** Wherever the problem is written out (rows, ghost-row previews, folded tags, pop-ups, hints, I'm stuck, spotlights, walkthroughs), a product is a middle dot between two bare numbers or a number and a bare x-term (`3 · 4`, `5 · x`), or the number next to its parentheses when the second factor is in parentheses (Flip's row `−1(−x) = −1(12)`, a fraction's `⅓(15)`, the folded tag `−1 · both sides`). The × stays only on the Moves panel (its floating symbol and the Multiply menu's option drawings) and on the distribute arcs' small drawing. A standing test (`tests/timesSign.test.js`) draws every card's states and fails on a × anywhere else.
- **Multiply's whole number on Fractions of x (rev 2.15, Build AA).** Live there, and only there today. Multiplying both sides by the fraction's bottom (`x/3 = 4` by 3) cancels the divide: the work row `3(x/3) = 3(4)` crosses off the multiplier and the bottom (the cross-off of 3G's numbers), and the new row is `x = 3(4)` when x is left alone (never worked out: the student types 12), or the new numbers (`2x = 18`) when a top is left. A number that does not cancel the bottom (`⅔x` by 2 makes `4/3 x`) is legal but not helpful: the spotlight, Undo, the reminder. Dividing on that card is helpful when it goes into the top and the other side (`⅔x = 6` ÷ 2 is `⅓x = 3`); into the other side but not the top makes the bottom bigger (spotlight); not into the other side fails as on Divide it. Either order is helpful. The one over a blank and the fraction option are greyed there with "That move unlocks on a later card." (the reciprocal is a Solve it Plus method), which a card may now do while Divide is live.
- **Flip everything** is its own panel button, not a Multiply option. On a card where Flip is greyed, a typed −1 gets that card's greyed message.
- A card turns moves and options on or off; the panel and the menu never change shape. A greyed option says "That move unlocks on a later card." (or "…later level." where a level gate applies), or the card's own reason (Two-step: "That move works once each side is one term."). Which are on: Divide it, Divide and Fraction (unit fractions), the whole number live but explained (rev 2.5: "5 × (5x) makes 25x: still not one x. Try dividing both sides.", and its `/` opens the fraction); Flip everything, Flip, and from saved Level 4 Divide and Fraction (−1/a in one move accepted); Two-step and Distribute, combine, solve, Divide and Fraction under the single-term rule; Add to both sides, no multiply-type move. Whole number is greyed on every other card today.

### 1D. Grabbing terms (manipulable equations)
- **The rewrite toggle (rev 2.15, Build AA, Fractions of x).** A fraction of x is one term written two ways: `⅔x` (a fraction times x) and `2x/3` (the x over the bottom, `x/3` when the top is 1); the stored term is the same in both (its top, its bottom), only its form differs. A tap or click on it in the newest equation (Enter or Space with the keyboard) writes the same equation in the other form as a row of its own, labelled "rewrite", foldable like any move, with Undo; it never changes a value. Resting the pointer on it (or a keyboard focus) shows a faint ghost of the other form under the equation. On either side of the =, on every level of the card. Help follows the form on the screen (§6). **The rewrite is drawn (rev 2.16, Build AC):** on the tap only (never on a redraw, a resize, a reload, Undo or a fold), in the room the new row will take, a short animation shows why the two forms are the same: about 3 s since rev 2.18 (Build AD; it was 1.5 s), each frame held for its own time, longest on the frames that carry the idea (`x/1` appearing and the dot, 0.85 s each; the other way, `x` split out as `x/1`, 1.1 s; the others 0.4-0.6 s); `?animslow=1` four times slower. `⅔x` → `2x/3`: the x lifts off the fraction, is written over 1 (`x/1`), a dot appears between the fractions (`⅔ · x/1`), the tops and bottoms join (`2x/3`; for `⅓x` the 1 on top is absorbed, `x/3`), and the row is printed. `2x/3` → `⅔x`: the top separates (`2 · x` over 3), the x is split out (`⅔ · x/1`), the `/1` drops (`⅔x`), and the row is printed. Dots only, never a times sign; a minus in front stays where it is. Any key or click finishes it at once (a second tap finishes it, then toggles); reduced motion: no animation, the row simply appears. No other row moves and the text size never drops for it. The stored term, the row and the class-sheet record are as before (the animation is not recorded).
- **Reorder** a term by dragging; **cross the midline** to flip its sign and write both-sides work automatically (constants today; x when x is on both sides); **combine** by dropping a constant on another (both light, rest greys out, the word "Combine" over them, a box below for the typed sum; auto-combine at later levels is a flag, off); **tap a minus** to make it `+ −2` (needed before distributing); **distribute** by dragging the whole factor onto the parentheses.
- **The wrong cancel (rev 2.8): a deliberate exception to "a legal move is never red".** An Add (a number or an x-term, by the button or by dragging across the =) that leaves 0 on one side and an x-term and a number together on the other (`5x = 3x + 10` + −5x makes `0 = 3x + 10 − 5x`) gets the spotlight (the 0 marked "nothing left", the other side lit): "We want the x-terms on one side and the numbers on the other. That Add took everything off one side. Undo, then cancel just one x-term." Only Undo. **Any sign (rev 2.9, Karl's rule):** the error is not separating the x-terms and the numbers onto opposite sides, so `2x = 3x + 6` + −2x (`0 = x + 6`) is flagged too. The hint after Undo never sends the student back to the same move: it opens Add's x-term option with the x-term on the side that holds the number, so the number ends alone on its side (`2x = 3x + 6`: "Add −3x to both sides: the 3x cancels, and the number is left alone on its side.", giving `2x + −3x = 6`; a negative number in front of x afterwards is fine, Flip handles it; where both sides hold a number, the smaller x-term), or, after a number, Add's number option with the opposite of the number beside x; recorded as `hint`, slip tag `zeroed-side`. The reminder at x on both sides (V1) follows the same rule: where one side is a lone x-term, it outlines the x-term on the other side. Two-step's and Add's own zero case (a lone number zeroed) keep their message.
- **Every drop works or says why (rev 2.7).** A term dropped where it can go moves (across the =, onto a like term, between terms; from either side of the =, whether or not the move before it has been folded). A drop that cannot work puts the term back with its reason: an x that would leave its only side (rev 2.8: its words end with a move that applies to that side's shape: move the number where there is one, divide at `ax = b`, type the value at x alone, combine or distribute first), a term onto an unlike term or a parenthesis ("Only like terms combine…"), a parenthesis's factor let go anywhere but its parenthesis. Dropped where it was, or away from the equation, a term simply goes back.
- **Distributing (rev 2.5, Build P).** When the factor is dropped on the parenthesis it is shown in colour with an arc to each piece inside, a small × on each arc, and "3 groups of" by the parenthesis; the blanks carry **no operation label** (the x blank keeps its printed x). After a wrong product the labels (`3 · x`, `3 · 2`) appear above the blanks as the scaffold (recorded as `hint`) for the rest of that problem; the next problem starts without them. **Undo after a wrong typed amount goes back to its blank (rev 2.8):** after a wrong product the distribute stays in progress (the factor in colour, the arcs, "3 groups of", the labels), the blanks empty and the cursor in the first, with "Try again: type what 3 · x and 3 · 2 make…"; after a wrong sum or a wrong worked-out product its two terms stay lit and its blank is empty and focused ("Try again: what is 19 − 4?"). No gesture is repeated. Add's amount already returned to its blank (Build A). A second Undo closes the blank.
- **Calculate a product (rev 2.5, Build P; rev 2.10).** After dividing first (or taking a fraction) a side can read `⅓(15)` (division form `(15)/3`). While x is not alone, the small dot between the factor and the number (rev 2.10; it was a ×; in division form, the fraction bar) is a button: it opens a blank for the signed product (like a sum's); Enter or Go writes the side as that one number (`x + 2 = 5`). A wrong product waits for Undo with the factor and number lit, then the hint ("⅓ · 15 is ⅓ of 15: split 15 into 3 equal groups and take one. Click the dot and type it."). Never at x alone (`x = ⅓(15)`): the student types x.
- **The invisible −1 and a fraction factor (rev 2.10, Build U, Distribute more).** A minus before a parenthesis with no number (`7x − (x − 6)`, `−(2x + 8)` at the start of a side) is tapped first: the factor `−1` appears in blue (`7x + −1(x − 6)`; tapping again puts it back). Dragging the bare minus onto the parenthesis is refused: "Tap the minus first: it means −1 times everything inside." Then the −1 is dragged like any factor, and every piece is typed with its 1 (`−1`, not `−`: "Type every piece, including the 1."). A fraction factor (`⅔(6x + 9)`, `−⅔(3x − 6)`) is one token, the stacked fraction with its sign, dragged onto the parenthesis; the blanks take the whole-number products (`4`x, `6`); the first look is "⅔ of" by the parenthesis with the arcs; after a wrong product the labels read `⅔ · 6x`, `⅔ · 9`. A negative fraction distributes in one step, signs and all.
- **While dragging:** a grey preview of the landing expression in place; the token is **green** (positive) and turns **red** over the midline with the new sign; the midline is thick and obvious and shown **only while dragging**; the destination side is tinted.
- **Dragging x** off an already-alone-on-the-left x gets the info pop-up "x is already on the left side of the equation. Let's keep x there. Try moving a number." Allowed when x is on both sides.
- Every drag has a tap or keyboard alternative; pointer events with a 6 px threshold; `touch-action: none` on grabbables.

## 2. The screen (bare, stable)

1. **Header and level dots:** shown for about 3 seconds at the start of each problem, then a thin strip; hovering the top brings them back.
2. **The solving space (left):** the equation, then rows of work (**older lines in lighter ink so the newest stands out**), then `x =` with **the one green button** to its right.
3. **The check space (right of the solving space):** empty until a value is checked (§4). No labels, a faint dotted line or space between.
4. **The moves panel (rev 2.13):** headed **"Moves"** (small and quiet), then **five square buttons**, one under the other, as large as fit at 1366×650 without lowering any card's text size (76 px; 88 px on a window at least 740 px tall; never under 56 px for touch). Each button carries **one large plain symbol and nothing else** (each with an accessible name): **+** Add, **×** Multiply, **÷** Divide, **×(−1)** Flip everything (one short label), and for Trade places **two curved arrows making a circle** (the recycling look, no equals sign, no plus or minus). The buttons do not draw the move's equation form: the **preview on the equation** shows the work on both sides. **No symbol floats beside a button** (rev 2.4's floating symbols are gone). Hover and focus show the move's **formal property of equality** (§5) and the preview; the pointer **approaching** (about 40 px) starts the preview early. The greyed look (dashed, still tappable for its message), the selected state (yellow fill and a thicker border, never colour alone) and the keyboard order are unchanged. **No goal lights on screen for students** (rev 2.13, Karl: "an extra detail students do not pay attention to"); they are still worked out for the helpful / unhelpful judgement, the class sheet and the nudges, and `?lights=1` (a teacher or debugging view, nothing students see) shows them beside the buttons as before. Nothing may overlap the panel: the touch keypad, the answer boxes, the work and the check space, and every pop-up keep clear of it (checked on every card at 1366×650 with touch, `tests/panelRoom.test.js`).
5. **Help is tucked** into a corner: **I'm stuck** flashes gently after **10 s of no action**; **Teach me** appears only after a **second error** on the problem, and flashes when it appears. Start over lives in the same corner.
6. **Keyboard first.** No number pad on devices with a keyboard; on touch devices a compact keypad pops up only while a field is focused.

### 2A. Pop-ups (one component, one rule)
- **Placement:** below wherever the action is; if there is no room, the nearest free space that covers **no equation or work**. It may cover greyed-out things such as the `x =` field.
- **Spotlight (error) pop-up:** dims the page, lights the error, message beside it, **Undo pulses with a hopping arrow** (steady arrow under reduced motion) and is the only exit. **I'm stuck / Teach me are ignored while it is up.** After Undo, a **hint pop-up** (the reminder rung) appears.
- **Info pop-up:** no dimming; closes on the next action.
- **Nudges** with nothing to undo ("type a number") are small pop-ups beside the field.
- The word "still here" after a move that fails to cancel sits below the number it points to.
- **Nudges for mechanical steps (rev 2.5).** After about **2.5 s with nothing happening** (any key, click or drag resets it), when the
  next step is **mechanical and there is only one thing to do**, the target glows and pulses for 1-2 seconds; if still nothing, a small
  pop-up says what to do (placed by the rule above, never over the equation or work) with a faint ghost of the action. Under reduced
  motion, a steady highlight instead of a pulse. It repeats gently, never stacks, never shows while a spotlight, error, scaffold or
  another pop-up is up, and clears on any input. Today's nudges: **combine** (a side holds two numbers or two x-terms that go together,
  x is not alone, nothing else is pending: "Drag one onto the other to combine them.") and **calculate a product** (`⅓(15)` beside a side
  that is not x alone: "Click the dot to work out ⅓ · 15." (rev 2.10); division form: "Click the fraction bar to divide 15 by 3."). **Choosing a move
  is never nudged:** that is the thinking, and it waits for I'm stuck. A nudge is not help and records nothing. The 10-second I'm
  stuck flash is separate and unchanged.

### 2B. Screen rules
- **One forward button.** **One big green button in exactly the same place on every screen** (right of `x =`). Only its word changes (Check, Next, Do it, Combine, Got it). Greyed when there is nothing to do. Enter presses it. No separate check mark.
- **Only one thing is lit at a time.** **No cursor or `x =` blinks** except the final `x =` step.
- **Nothing advances on a timer** except the problem-start header fade and the help-flash timers above.
- **Layout is stable;** no reflow when a row is added. **Phones are secondary:** Chromebooks and laptops first; every drag has a tap alternative.
- **A redraw changes only what changed (rev 2.7).** An entrance or cross-off animation plays once, when its row or mark first appears. A redraw for any other reason (a pickup, a key, a click, Undo, a hover, a pop-up, a nudge) leaves every row already on screen exactly as it was: never replayed, never blanked, never taken off and put back. Picking up a term leaves a dashed gap where it was and changes nothing else.
- **Never grey out what the question is about.** Whatever the student is being asked about (the numbers in `−8 + 11`, the equation being solved, the two sides that failed to balance) stays at full strength and readable during any pop-up, spotlight or scaffold. Other things grey around it.
- **Answers:** one whole number typed into `x =` (or the blanks); on Strange solutions, a fraction too (rev 2.11, §4A). The solved value is never displayed before the student types it.

## 3. The work stack in detail
*(unchanged from rev 1.2 except as noted)*

- **3A. Folding.** Only the current move shows full work; **Next** folds it to one row. **Undo reaches only the unfolded move.** Start over wipes the stack.
- **3B. Fit.** The generator reports the worst-case row count; Claude Code renders it at 1366×768 and 1366×650; if it fails, **fold more, never shrink text.** The check space (§4) uses the same reserved height. **One text size a problem (rev 2.7):** the size is chosen once, when the problem starts, from that problem's worst case (its honest path played ahead: the most rows, the widest row, the longest check, drawn out of sight at the window's size), the largest of 46/42/38/34/32 px at which nothing scrolls, no row runs past its space, and the check's pop-up has room away from `x =`; it never changes while the student works the problem (a row added or folded, a pop-up, the check, Undo, Start over). A new window size chooses again. **Row room (rev 2.9):** every row is tall enough for the tallest thing a row can hold (a division row with its bars and blanks, a group, a fraction, a cross-off), so nothing a lit area, outline, blank or pop-up anchor draws crosses into the next row, and the Divide row's "Same as multiplying by 1/5." line has a reserved line of its own. The extra room never lowers the chosen size: a problem that no longer fits folds sooner. **Parentheses (rev 2.16, Build AC):** a pair of parentheses is as tall as the tallest thing inside it (a stacked fraction, a fraction of x, a division), with the weight of the text beside it, everywhere in Solve it (work rows, previews, checks); one shared drawing piece does this, and parentheses round plain text stay the font's own. Taller parentheses never lower the chosen size either.
- **3F. A move whose signs cancel (rev 2.7).** A flip (written `−1(−x) = −1(12)`, rev 2.10: no times sign), or dividing by a negative, crosses each cancelling minus with a vertical stroke so it reads as a plus (a shape, never colour alone; rev 2.8: centred on the minus's bar, as far above it as below, never a T), one minus at a time, about 1.3 s each, then the row they make comes in. Reduced motion: both pluses drawn, still. **It can be skipped (rev 2.9):** any key, click or Next finishes it at once and goes on. The cross-off of the numbers (the two 3s) is unchanged.
- **3G. The Add cross-out (rev 2.13, Karl; gentler since rev 2.14, Build AB).** Each cancelling term of an Add (a number or an x-term, by the button or by dragging across the =) is crossed out **whole, sign and all** (`+8`, `−3x`), by **one thin straight stroke from the lower left to the upper right at about 30°** (25-30°: shallower on a wide term so it rises no more than about 15% above the digits), **its midpoint on the centre of the term's ink** (the digits' middle, anchored to the baseline; never between the sign and the digit, never under the number), 0.075em heavy (3 px at 40 px text, at least 2 px), about 0.05em past each end, in the cancel red, **drawn behind the glyphs**. It must never read as an underline. It draws itself from the lower left once, when its row first appears (never again on a redraw), then the term's ink fades as before while the stroke stays at full strength; reduced motion: drawn still. In a stacked Add (an x-term, Build T; a number, Build Y) both partners are crossed the same way (the term; the `+` in front of the lower one is the column's adding sign). The cross-off of the numbers in a divide or a fraction (the two 3s, rev 2.7) keeps its slant and timing; a flip's vertical strokes through the minus signs (3F) are unchanged.
- **3C. Highlighting each step.** The operation about to happen is coloured and **bold** (colour plus bold, never colour alone); its result appears in the same colour next line; one pair at a time; accent is unique (not green, red, blue or the added-amount colour). Never underline a row.
- **3D. The operation is blue** wherever it appears (prompts, pop-ups, rows, evidence).
- **3E. Work is shown at every step on every level**, evidence included.

## 4. Checking a value (side by side)

1. The student types a value in `x =` and presses the green **Check**. **Everything greys out except the original equation and the check space.** Pop-up: "Drag your value into each x." The typed value and every x blink. After 2.5 seconds with nothing done, a faint copy of the value travels from `x =` to the first x, again and again until the student acts.
2. **Drag the value onto each x** (every card). **Picking the value up** slides a faint shadow copy of the equation being checked into the check space, at the place its first line will take (the same faint look as the travelling value). **Dropping it on an x** makes the copy solid; **dropping it anywhere else** slides the shadow back and changes nothing. **Multiple x's need a drop each (rev 2.5), on every card:** while the value is dragged every empty x glows as a drop target; a drop fills that x only, with a small green check above it, and the other empty x's show a faint ghost of the value waiting; the copy completes and the steps begin once every x has the value. Nothing fills itself.
3. **The check, top to bottom (Build I):**
   - **Line 1: the equation being checked, exactly as written**, every x in the same blue as the x in the original.
   - **Line 2, directly below it: the same equation with the value in each x's place**, the value in blue (in parentheses when negative, as the rendering rules below say). **Each value sits directly under the x it replaced**, so the blue pairs read "this x became this number." A value wider than x moves the rest of line 2, never the pairing; if the first value reaches left of where line 1 starts, line 1 moves right as a whole. Line 1 is never stretched or squeezed, **except with several x's (rev 2.6): the two lines share one column grid**, so where a value is wider than its x (`2 × 7` under `2x`) line 1 opens a space before that x instead, and each blue value sits directly under its x. *(Known limit, two x's only: when a number in front of the second x adds a "2 ×" to line 2, the second value can sit to the right of its x; no card has two x's yet.)*
   - **Then one step per press of the green Next** (rev 2.12: a step is every operation of one kind, on both sides at once), ending **✓ Balanced** (green) or **✗ Not balanced** (red). A wrong value lights the last row and Not balanced.
   - **On the seesaw** (opened by I'm stuck or Teach me), the balance mirrors the check: the original equation with an empty x box while the value waits (line 1), the x box swapped for the box of counters when it lands (line 2), then each line's combining.
   - The check space has one more row than before: 4 rows at worst (line 1, line 2, one worked line, the mark) on Add to both sides and Divide it; rendered at 1366×768 and 1366×650.
4. **No text ever covers the equation.** The rendering rules carry over: negative values in parentheses; **a product is written with parentheses, never with a times sign (rev 2.8)**, since × next to the x's reads as another x: `7(3)`, `−3(−4)`, `2(7)`, `3(3 + 2)`, at most a dot between two numbers (rev 2.10: the same rule holds for every written row, not only the check, §1C); test cases `3x = −12`, −4 → `3(−4) = −12` · `−3x = 12`, −4 → `−3(−4) = 12` · `12 = −x`, −12 → `12 = −(−12)` · `7 = x + 3`, 4 → `7 = 4 + 3`.
5. **Wrong value pop-up:** "When x = 19, the equation is not balanced." (never "put 19 back into x"). Undo resets to before the guess.
6. **No collapsing (rev 2.5), one kind of operation a press (rev 2.12, Karl).** Every check on every card, at every level, shows the order of operations, ending Balanced or Not balanced, and each press of Next or Enter does every operation of one kind at once, on both sides: first inside the parentheses, then every product (each x's number times the value, a factor times its parenthesis, the opposite of a number), then (with fractions) every whole number written over the denominator, then every run of numbers added together in one go. `3(4) + 4 = 4 + 9`, `12 + 4 = 4 + 9`, `16 = 13`; `2(7 + 7) + 9 = 5(7) + 2`, `2(14) + 9 = 5(7) + 2`, `28 + 9 = 35 + 2`, `37 = 37`. (Rev 2.5 to 2.11 did one operation a press; Karl found it too slow.)
7. **The note while the value waits (rev 2.12).** "Let's check that x = 7 is the solution. Drag the 7 onto an x above." sits low in the empty check space, never over the value or the way from it up to the equation.

8. **A fraction is simplified on the next line (rev 2.18, Build AD; Karl, 2026-11-03).** A fraction may appear on the line whose step produced it (every step is still shown), but the next line writes it in its simplest form, everywhere in the line (inside a sum, a product or parentheses): a fraction equal to a whole number becomes that number (`−20/5` → `−4`, `−6/3 + 6` → `−2 + 6`); one not in lowest terms goes to lowest terms (`10/4` → `5/2`, `33/6` → `11/2`); one already in lowest terms stays a fraction, proper or improper (`7/5`, `−8/5`, `56/3`), never a mixed number or a decimal. Simplifying is its own step, the first kind of operation (every fraction that needs it, on both sides at once). Two kinds of fraction are written over a bottom on purpose and stay until their next step: a number written over the common bottom so it can be added (`15/2 + 4` → `15/2 + 8/2` → `23/2`), and the two sides written over one bottom to compare them at the end of a Not balanced check (`5/2 = 7/3` → `15/6 = 14/6`). Each sum's result is simplified on its next line. A wrong value's check follows the same rule on both sides. Unchanged: a line is never rewritten after it appears, the order of operations, how a typed answer is judged, the work rows. (Today only Strange solutions' check substitutes fractions that can need it; Fractions of x's check already wrote each result simplest; every other card substitutes whole numbers only.)

### 4A. Answer kinds (rev 2.11, Strange solutions)
- **A whole number** (every card), typed into `x =`.
- **A fraction** (Strange solutions only): `x = [ ]/[ ]`, a box for the top and a box for the bottom, drawn stacked. Digits go into the top; `/`, Tab or ↓ go to the bottom, Shift+Tab or ↑ back; a click on a box clears it for retyping. A whole number is typed in the top alone (the bottom is then 1). The minus is typed in the top. A decimal point gets "Write it as a fraction, like 5/2." No mixed numbers. The touch keypad has a `/` key here.
- **Not simplified** (`15/6`, `4/2`): never red, no check. A nudge beside the field, "Can you simplify this further?", and the student retypes; after a second unsimplified try it adds "Divide the top and the bottom by the same number." (recorded `hint`). Tag `unsimplified`; not a wrong answer.
- **The check with a fraction:** the value is one stacked token, dropped into every x (one drop each). The steps show everything: the products (`3(5/2)` → `15/2`), any fraction that can be simpler simplified on the next line (rev 2.18, item 8: `−24/3 + 7` → `−8 + 7`), a whole number written over the denominator when it meets a fraction (`15/2 + 4` → `15/2 + 8/2`), the sums, ending `23/2 = 23/2` Balanced or Not balanced. Products in parentheses; a negative fraction in parentheses with its sign on the top.
- **Dividing never fails on Strange solutions:** dividing by the number in front of x writes `x = 15/6` (nothing worked out for the student). A divide by another number that would leave a fraction beside x is not made: "Divide by 6, the number in front of x."
- **x = 0** (Strange solutions only) is an answer like any other. It is never what a student types for "no solution": when x disappears, `x =` is greyed (rev 2.20).
- **No x left** (rev 2.20, Strange solutions Levels 4-5): when an Add (either option), a combine or a drag leaves no x anywhere, the equation is a statement with no x (`3 = 7`, `3 = 3`, `0 = 0`). `x =` greys with the note "x disappeared. What does the equation say?" and two buttons appear beside it in the answer row (a fixed place, nothing covered; real buttons, Tab and Enter): **"No solution"** with the smaller line "never balanced", and **"Infinitely many"** with the smaller line "always balanced". Two opposite x-terms combined on a side make 0 (typed `0` or `0x`) and the term drops from the row. The reminder for the state (shapes NT, NF): "x disappeared. Is this statement ever true?", at the buttons.
- **A conclusion** (rev 2.20): the statement is the check. A right pick confirms in the words of the balance ("3 = 7 is never true, so no x can work. The sides never balance." / "3 = 3 is always true, so every x works. The sides always balance.") and the green button becomes Next; recorded as solved. A wrong pick is an error: the final statement lit (never greyed), "3 = 7 is false. It is false whatever x is." (or "3 = 3 is always true.") with Undo, then the reminder; tag `conclusion-wrong`, recorded in the answers column as the button's words.
- **Try a number** (rev 2.20): after a right pick, an optional button. It runs the usual check on the original equation with any number the student types (a fraction too; one drop per x), never graded, never red, no Undo, nothing recorded. When the check ends the balance picture appears in the right-hand space (drawn in Karl's look from his "Balanced or Not?" page: a block stamped with the tried value for each x, a green ball for a positive number and a red balloon for a negative one, a dashed 0 block when the value is 0, the totals with their working under the pans, the beam tilting toward the heavier side, capped, snapping under reduced motion), with one line from the exact values ("x = 3/2. Right side is heavier by 4." or "x = 3. Balanced.") and the pattern line after it ("Try another number: it is still heavier by 4." / "Try another number: it balances every time."). The balance shows only what the student tried. Not in a no-help attempt.
- **Unsimplified tries** are listed in the class sheet's answers column (`15/6 → unsimplified`), clearly not wrong (rev 2.20).

## 6. Help

**Principle:** every support is something the student **does**, and ends by sending them back to try. Nothing opens automatically except the post-error sequence (§2A) and the forced-move pop-up.

- **Nudges are not help** (rev 2.5, §2A): a mechanical step with one thing to do is nudged after about 2.5 s; choosing the move waits for I'm stuck. Nothing is recorded.
- **Help talks in the form on the screen (rev 2.8).** A row made with the Divide button (drawn with a fraction bar) gets division words ("x is 15 divided by 3. Work it out, then type x."); a row made with the Fraction option (drawn `⅓(15)`) gets fraction words ("x is ⅓ of 15. Work it out, then type x."). Every reminder, hint after Undo, I'm stuck rung, refused drag, product pop-up and failed-division pop-up follows this; a division that does not come out even is said as one ("Press Undo and try another number to divide by."), and the choices after Undo are numbers to divide by (÷ 2 … ÷ 6, the Divide button lit). Before anything is divided, the hint naming the move may give both ways ("divide both sides by 5 (that is, multiply by ⅕)"). The row's own line "Same as multiplying by ⅕." is part of the division row, not help. A standing test checks every shape on every card in both forms.
- **A model as the first scaffold (rev 2.15, Build AA).** On Fractions of x the box cut into equal parts (in the look of Group It's fraction walk) is I'm stuck's first click and the hint after a wrong value and Undo, and is drawn on its own on the first problem of a level that meets a new kind of fraction (Levels 1 and 3). It sits in the right-hand space (never over the work, never with the check) and every step is done by the student: the cut, the parts the top names, what one part makes (typed; the app then writes the equation for one part as a row labelled "one part", `⅓x = 3`), the other parts filled, then x typed in `x =`. The second click is the reminder, which then repeats. Its words are in its own caption.
- **The help order on Fractions of x, by level (rev 2.16, Build AC; Karl).** The model is the first help only on the model-first levels, **1 and 3**: I'm stuck's first click is the model, the second the reminder (the move, in the form on screen), which then repeats; the hint after a wrong value and Undo is the model. On **Levels 2, 4, 5 and 6** the move comes first: the first click is the reminder ("Multiply both sides by 3 to cancel the divide by 3."; on a non-unit fraction too, rev 2.19: "⅔x means ⅔ of x. Multiply both sides by 3 to cancel the bottom 3.", then at `2x = 18` "Divide both sides by 2."; dividing by the top first stays helpful), the second draws the model on the current equation (never on its own), the third repeats the reminder; the hint after a wrong value and Undo is the reminder. **A negative fraction asks for −1 first:** with a minus in front of the fraction (`−⅔x = 6`) the reminder is "Multiply both sides by −1 first." with Flip everything lit, and the model, asked for before the flip, says "Multiply both sides by −1 first, then I can draw the box." (Flip everything lit; recorded as `hint`); once flipped it draws from the current equation. A negative on the right only (`⅔x = −6`) draws parts worth negative amounts. **The model by itself once per device:** it is drawn on its own the first time this device reaches the first problem of Level 1, and of Level 3, then never again (one click away). Remembered in the browser only, never in the save code, sync or class sheet; storage refused means it is drawn each time. `?model=auto` brings it back for testers.
- **Hint pop-up after Undo (the reminder rung).** Lights the needed move with its hover preview and the suggested amount where it helps. **When the next move is dividing (rev 2.9)** (`5x = −15`, `3x = 15` after a combine, a group after Distribute, `−3x = 12` on Flip), the hint shows a multiplication dot between the number and the x in that row (`5 · x`, only while the hint shows) and the Divide button's preview (the fraction bars with the box beneath); nothing is boxed. The same is I'm stuck's first rung; the second is the card's model picture ("Model it": boxes equal to the amount, the amount dealt out) where the card has one.
- **I'm stuck** (one rung per click, +1 stuck count): Model it / Choose the move / Guided; rungs restart at each new state; every rung gives the student something to do.
- **Teach me** is the same scaffolds on a forced path. On Add: pop-up "To cancel the +8 we add its opposite, −8, to both sides", **Add lit with its preview and the blank pre-filled**; the green button "Do it"; at x alone the Party/Battle bubble; then the counters walk if still stuck. It never writes the final value.
- **Party / Battle** (Karl's words): party = same signs join; battle = opposite signs, the bigger team wins. **The bubble always floats directly above the two numbers or counters in question, with everything else greyed out.** Afterwards the student crosses off opposite pairs (tap each counter or a whole box; automatic crossing allowed); **crossed-off counters stay visible** (struck through or faded) while the student counts what is left. Numbers over 12 use the big-number walk (no counters).
- **Misconception pop-ups by typed value:** typed the opposite of the number next to x (`x + 8 = …`, typed −8): "−8 is an important number, but it's not the value of x. It's what we add to both sides to find x." Then the hint lights Add with −8. Added the sizes (`−8 + 11` → 19, tag `sizes-added`): after Undo, Party/Battle above the operation. Cards may add one named misconception each.
- **Scaffold rules carried over:** a scaffold never blanks the stack; the picture stays until Next; every rung that has a picture shows it, including x alone with an unevaluated side; numeric levels offer no help.
- **Stuck count (teacher-visible):** per level, I'm stuck clicks and Teach me uses; anonymous scrambled ids only (hard district rule). The class sheet shows lights/goals per student (teacher view); words `hint`, `model`, `move`, `guided`, `crossoff`, `forced` and save-code meaning (v14) do not change.

## 7. Levels, numeric levels and the diagnostic
*(unchanged)* Five problems per level, no repeated answers; a new single-move card opens with a numeric level (no x, balance readout on) that can be skipped only after the diagnostic; combined-move cards have none. Save codes hold one bit per level; **displayed Solve it level numbers are one lower than saved** (Level 1 now goes straight to problems; "See why it works" is a button). Old levels map forward.

- **The no-help choice (rev 2.19, Build AE; it was "test out of a locked level", rev 2.17, Build Z).** A level is entered with help or by trying it with no help. A fresh open, displayed level of a Solve it or Solve it Plus card (nothing placed or earned, no problem started) opens a small panel: "Start with help" (the default, focused; today's level) or "Try with no help" ("2 problems"); Escape or a tap outside leaves the student on the card; no chooser on a level in progress, placed or earned, on Count it or Build it, or on a link with `seed=` (unless `choose=1`, for testers) or `choose=0`. A pass on an open level places it the same way ("No help needed!"); a miss, Give up or leaving on an open level carries on with help on the same problem, the problems solved counting on the level, and the level is then in progress. A locked, displayed level can be tapped too: the same panel with "Try with no help" and Not now (focused). The locked level's note, where the level popup shows it, reads "Finish Level N or tap to skip ahead." (rev 2.18). The attempt is the level's first two problems for a fresh seed, played on the card in a **no-help mode**: no I'm stuck and no Teach me (hidden, and the actions ignored), no spotlight of any kind (no error pop-up, no hint after Undo, no question), no nudge and no idle flash, no model drawn by itself, nothing pointed out once a level (Trade places, the flip, dividing by a negative, the rewrite's instruction), no forced move, and no message on the line beyond the check's own words (placing the value, plugging it in, Balanced, Not balanced; on Strange solutions also "Can you simplify this further?"). A move that waits for Undo still waits for it (its Undo outlined), and Start over works even then. The moves, previews and the check are as always. **Independent** means the first value checked (a guess before x is alone, or the final value) is right: a wrong one ends the attempt once its check reaches "Not balanced"; Give up ends it too (on an open level both carry on with help, above). Both right: the level and every displayed level below it are placed (silver, Build X) and the next opens; the student earns gold with one more problem: **a placed level (by any route) opens on its last problem, problem 5 of 5, the four dots before it silver** (rev 2.20), and solving it finishes the level. On Strange solutions (rev 2.20) the conclusion buttons are the answer in an attempt (the first pick counts as the first value checked); "Try a number" and the balance are help and do not appear. On a locked level a fail never lowers anything and can be tried again at once with new problems. The bar reads "No help · Level 3 · Problem 1 of 2 · Give up" on both doors. Each problem of an attempt is logged with `test-out-pass` or `test-out-fail` (a miss on an open level: the attempt's rows, the problem with the miss included, `test-out-fail`; the rest of the level as usual). One switch for the whole page (`engine/noHelp.js`), on only during an attempt; the session is cleaned after every action (`engine/testOut.js`).
